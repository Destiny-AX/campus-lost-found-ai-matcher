# 拾寻多账号支持实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现真正的多用户视角与操作流程，让不同账号在系统中拥有独立身份、独立数据视图和完整的交互闭环。

**Architecture:** 基于现有 JWT + localStorage 认证体系，扩展多账号本地管理（token 列表存储）+ 后端权限隔离（owner_id 校验）+ 管理员角色。前端增加账号切换器，后端增加操作权限校验。

**Tech Stack:** HTML/CSS/JS 前端，Node.js Vercel Functions 后端，Supabase PostgreSQL，自实现 HS256 JWT。

---

## 当前状态分析

### 现有认证架构
- **登录方式**：微信 Mock 登录（生成随机 openid）+ 游客登录
- **身份存储**：JWT token 存 `localStorage`（`shiyun_auth_token`），单账号
- **用户识别**：后端通过 `Authorization: Bearer <token>` 提取 JWT payload 中的 `sub`（user_id）
- **数据隔离**：`lost_found_records.owner_id` 已存在，但后端 `handleUpdate`/`handleDelete` 未校验操作者是否为 owner
- **角色体系**：无角色区分，所有用户平等

### 核心问题
1. **单点登录**：一个浏览器只能记住一个 token，切换用户必须重新登录
2. **无权限校验**：用户 A 可以修改/删除用户 B 的记录（只要知道 record id）
3. **无管理员视角**：无法审核、管理所有记录和用户
4. **无多账号切换 UI**：没有账号列表、切换、登出全部等功能

## Task 1: 后端权限基础——角色字段与权限校验

**Files:**
- Modify: `api/auth.js`
- Modify: `api/records.js`
- Modify: `api/_shared.js`

### 背景
当前后端没有任何权限校验，任何登录用户都可以修改/删除任意记录。需要在用户表增加 `role` 字段，并在关键操作前校验 `owner_id`。

### 步骤

- [ ] **Step 1: auth.js 的 createUser 增加默认 role**

在 `createUser` 函数（或 `handleWechatLogin`/`handleGuestLogin` 中调用处）确保用户创建时带有 `role: "user"`：

```javascript
const user = await createUser({
  nickname,
  avatar_url: avatarUrl,
  wechat_openid: openid,
  login_provider: "wechat_mock",
  role: "user",
});
```

- [ ] **Step 2: auth.js 的 JWT payload 增加 role**

在 `handleWechatLogin` 和 `handleGuestLogin` 生成 token 时：

```javascript
const token = signJwt({
  sub: user.id,
  nickname: user.nickname,
  provider: current.provider,
  verified: user.is_verified,
  role: user.role || "user",
});
```

- [ ] **Step 3: records.js 的 handleUpdate 增加权限校验**

在 `handleUpdate` 开头增加：

```javascript
const current = getCurrentUser(req);
if (!current) { sendJson(res, 401, { error: "未登录" }); return; }

// 查询原记录
const config = getSupabaseConfig();
const getRes = await supabaseFetch(config, `/rest/v1/lost_found_records?id=eq.${encodeURIComponent(id)}&select=owner_id`, { method: "GET" });
const rows = await getRes.json().catch(() => []);
const record = rows[0];
if (!record) { sendJson(res, 404, { error: "记录不存在" }); return; }

// 仅 owner 或 admin 可修改
if (record.owner_id !== current.sub && current.role !== "admin") {
  sendJson(res, 403, { error: "无权修改此记录" });
  return;
}
```

- [ ] **Step 4: records.js 的 handleDelete 增加权限校验**

类似 Step 3，在删除前校验 owner_id。

- [ ] **Step 5: records.js 的 handleClaimRequest 增加权限校验**

确保 claimant 不能认领自己的记录：

```javascript
if (record.owner_id === current.sub) {
  sendJson(res, 400, { error: "不能认领自己的记录" });
  return;
}
```

## Task 2: 前端多账号 Token 管理

**Files:**
- Modify: `script.js`

### 背景
当前只用一个 `localStorage` key 存 token。需要扩展为存储多个 token（账号列表），并支持切换。

### 步骤

- [ ] **Step 1: 增加多账号存储常量**

```javascript
const AUTH_TOKEN_KEY = "shiyun_auth_token";
const ACCOUNTS_KEY = "shiyun_accounts"; // 存储所有登录过的账号列表
```

- [ ] **Step 2: 增加账号管理工具函数**

```javascript
function getAccounts() {
  try { return JSON.parse(localStorage.getItem(ACCOUNTS_KEY) || "[]"); } catch { return []; }
}
function saveAccounts(list) { localStorage.setItem(ACCOUNTS_KEY, JSON.stringify(list)); }

function addAccount(token, user) {
  const list = getAccounts().filter(a => a.id !== user.sub);
  list.unshift({ id: user.sub, nickname: user.nickname, token, avatar: user.avatar_url || "" });
  saveAccounts(list);
}

function switchAccount(accountId) {
  const acc = getAccounts().find(a => a.id === accountId);
  if (!acc) return false;
  localStorage.setItem(AUTH_TOKEN_KEY, acc.token);
  currentUser = decodeJwtPayload(acc.token);
  updateAuthUI();
  renderAll();
  showToast(`已切换到 ${acc.nickname}`, "success");
  return true;
}

function removeAccount(accountId) {
  const list = getAccounts().filter(a => a.id !== accountId);
  saveAccounts(list);
  // 如果删除的是当前账号，登出
  if (currentUser && currentUser.sub === accountId) {
    handleLogout();
  }
}
```

- [ ] **Step 3: 修改 handleWechatLogin 和 handleGuestLogin，登录后保存到账号列表**

在登录成功、设置 `localStorage.setItem(AUTH_TOKEN_KEY, data.token)` 之后：

```javascript
addAccount(data.token, data.user);
```

- [ ] **Step 4: 修改 handleLogout，保留账号列表但清除当前 token**

```javascript
function handleLogout() {
  localStorage.removeItem(AUTH_TOKEN_KEY);
  currentUser = null;
  updateAuthUI();
  renderAll();
  showToast("已退出当前账号", "info");
}
```

- [ ] **Step 3: script.js 增加 renderAccountList 函数**

```javascript
function renderAccountList() {
  const container = document.getElementById("accountList");
  if (!container) return;
  const accounts = getAccounts();
  const currentId = currentUser?.sub;
  container.innerHTML = accounts.map(a => `
    <div class="account-item ${a.id === currentId ? 'is-current' : ''}" data-account-id="${escapeHtml(a.id)}">
      <span class="acc-avatar">${a.avatar ? `<img src="${escapeHtml(a.avatar)}" style="width:100%;height:100%;border-radius:50%">` : '👤'}</span>
      <span class="acc-name">${escapeHtml(a.nickname)} ${a.id === currentId ? '<span style="color:var(--primary);font-size:12px">当前</span>' : ''}</span>
      <span class="acc-remove" data-remove-id="${escapeHtml(a.id)}">移除</span>
    </div>
  `).join("");

  container.querySelectorAll(".account-item").forEach(el => {
    el.addEventListener("click", (e) => {
      if (e.target.classList.contains("acc-remove")) {
        const id = e.target.dataset.removeId;
        removeAccount(id);
        renderAccountList();
        return;
      }
      const id = el.dataset.accountId;
      if (id !== currentId) {
        switchAccount(id);
        renderAccountList();
      }
    });
  });
}
```

## 假设与决策

1. **角色体系**：仅区分 `user` 和 `admin`，admin 可管理所有记录
2. **账号存储**：本地 `localStorage` 存储多个 token，不存密码
3. **向后兼容**：旧用户无 `role` 字段时默认视为 `user`
4. **游客账号**：游客登录也纳入账号列表管理
5. **安全**：后端所有写操作都必须校验 owner_id 或 admin 角色
