# 登录状态刷新、测试数据清理与机构联系方式完善

## 概述

本次优化解决三个核心问题：
1. 登录/退登/实名认证成功后刷新页面，使信息模糊化状态实时更新
2. 移除首页的 6 条硬编码测试数据，让数据完全来自后端
3. 确保代保管公共机构展示完整的联系方式

## 当前状态分析

### 问题 1：登录状态变更后不刷新页面
- **位置**：`script.js` L326-L383（handleWechatLogin/handleGuestLogin/handleVerifyIdentity）和 L944-L950（handleLogout）
- **现状**：登录后只调用 `updateAuthUI()` + `renderAll()` 重新渲染，但记录数据仍使用旧的（已模糊化的）
- **影响**：登录后看到的信息仍是模糊的，需手动刷新页面才能看到完整信息

### 问题 2：首页存在 6 条测试数据
- **位置**：`script.js` L66-L115（`initialRecords` 数组）
- **内容**：蓝色校园卡套、蓝色学生卡、黑色双肩包、白色耳机充电盒、黑色折叠伞、银色钥匙串
- **影响**：每次加载都会显示这些数据，与真实数据混淆

### 问题 3：代保管机构联系方式展示不完整
- **位置**：`script.js` L780-L809（`renderInstitutionContact` 函数）
- **现状**：机构种子数据有 `contact` 字段（如 "021-12345678"），但模糊化状态下会被隐藏
- **影响**：用户无法查看机构联系方式，导致"无法联系"

## 实施计划

### 步骤 1：修改登录/退登/实名认证函数，添加页面刷新

**文件**：`script.js`

**修改内容**：

1. **handleWechatLogin**（L326-L345）：
   - 登录成功、token 存储后，调用 `window.location.reload()` 刷新页面
   
2. **handleGuestLogin**（L347-L362）：
   - 游客登录成功后，调用 `window.location.reload()` 刷新页面

3. **handleVerifyIdentity**（L364-L383）：
   - 实名认证成功后，调用 `window.location.reload()` 刷新页面

4. **handleLogout**（L944-L950）：
   - 退出登录后，调用 `window.location.reload()` 刷新页面

**修改原则**：
- 在 `localStorage.setItem()` 之后调用 `reload()`，确保 token 已持久化
- `reload()` 会让 `restoreAuth()` 读取新 token，从而更新 `currentUser` 状态
- 刷新后后端会根据新的认证状态返回完整/模糊化的数据

### 步骤 2：移除 initialRecords 测试数据

**文件**：`script.js`

**修改内容**：

1. 删除 L66-L115 的 `initialRecords` 数组定义
2. 修改 `loadRecords` 函数（L449-L459），移除对 `initialRecords` 的引用：
   - 删除 `const seedRecords = await Promise.all(initialRecords.map(hydrateRecord));`
   - 直接返回 `remoteRecords`
3. 保留 `hydrateRecord` 函数（可能被其他地方调用）

### 步骤 3：确保代保管机构联系方式完整展示

**文件**：`script.js`

**当前逻辑**（L780-L809）：
```javascript
if (fuzzy) {
  institutionDiv.classList.add("fuzzy");
  institutionDiv.innerHTML = `<span class="fuzzy-notice">🔒 实名认证后查看保管方联系方式</span>`;
}
```

**问题**：模糊化状态下完全隐藏了联系方式

**修改方案**：
- 对于代保管公共机构（`item_status === "institution"`），联系方式应始终展示，不受模糊化影响
- 理由：公共机构联系方式是公开信息，无需实名认证即可查看

**具体修改**：
1. 在 `renderInstitutionContact` 函数中，检查记录的 `item_status`
2. 如果是 `institution` 类型，即使 `is_fuzzy` 也为 true，也展示机构联系方式
3. 保持 `custody`（个人代保管）类型的模糊化逻辑不变

### 步骤 4：验证首页登录组件正常工作

**检查项**：
- 登录弹窗（`#loginDialog`）的打开/关闭
- 微信登录表单提交
- 游客登录按钮点击
- 实名认证弹窗的打开/关闭
- 认证表单提交

**位置**：`script.js` L161-L200（bindEvents 函数）

**现状**：事件绑定使用了安全的 `on()` 辅助函数，DOM 元素不存在时不会报错。需确认 DOM 元素 ID 与脚本中的引用一致。
