# 拾寻离线 Evaluation 标注指南

> 离线小规模标注集，不代表线上真实用户表现。

## 数据来源

`dataset.json` 中的 28 条查询和 18 条候选均为本轮人工设计、人工标注的合成案例。它们不来自线上点击、展示、通知、认领或运营数据，也不包含真实联系方式与个人身份信息。

`image_key` 只映射到确定性的本地图像特征夹具，用于验证融合代码是否正确使用图像维度；它不能证明真实照片域上的图像识别或图像匹配准确率。

## 正例定义

- 正例必须与查询描述指向同一件物品。
- 一条查询允许 1—3 个正例；描述过于宽泛且确实可能对应多个候选时，可标注多个正例。
- `positive_ids: []` 表示人工判断候选池中没有正例。
- 相同类别或颜色不足以构成正例。
- 地点接近但隐藏特征冲突、时间明显冲突或品牌／外观不一致时标为负例。

## 困难样本要求

数据集覆盖同类别、同颜色、近地点、时间冲突、缺字段、多正例和无匹配样本。每条查询的 `difficulty` 字段记录评测目的。修改标签时必须同步给出理由，不得为了提高指标而调整正例。

## 指标口径

- HitRate@K：只在存在正例的查询上计算，前 K 是否至少包含一个正例。
- MRR：只在存在正例的查询上计算，第一个正例排名倒数的平均值。
- 通知阈值误匹配率：所有得分达到 75 的候选中，非人工正例的占比，是离线误通知代理指标。
- 无结果率：最高候选分低于 40 的查询占比。
- 结果覆盖率：至少一条候选得分达到 40 的查询占比。
- Top-1 平均证据覆盖：Top-1 候选实际可用维度权重覆盖率的平均值。

## 复核流程

1. 一人先标注查询与正例。
2. 第二人独立确认正例。
3. 分歧样本保留书面理由后裁决。
4. 当前版本尚未完成双人独立复标，因此不能宣称标签具备正式研究级一致性。
